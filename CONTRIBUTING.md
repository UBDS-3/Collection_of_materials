# Contributing teaching material

You do not need to clone this repository to submit a notebook, lecture, or
other teaching material. The recommended route is the GitHub web interface.

## Submit from a browser

1. Open the repository on GitHub and navigate to the destination folder below
   `content/`.
2. Select **Add file → Upload files** and drag in the notebook, source file,
   slides, or supporting assets.
3. Choose **Create a new branch and start a pull request**. Do not commit
   directly to `main`.
4. Describe the material in the pull request and complete the checklist.
5. A maintainer reviews and merges the pull request. The Pages workflow then
   regenerates navigation and publishes the site automatically.

The **Check material submission** workflow runs on the pull request before
review. It checks dataset limits and exercises the browser-copy and navigation
generators; the deployment workflow performs the full Quarto render after merge.

If you do not have write access, use **Fork this repository** first. The same
browser upload flow works in your fork, and GitHub will offer to open a pull
request back to this repository.

## Choose a destination

| Material | Folder |
| --- | --- |
| Introductory R | `content/r-basic/` |
| Introductory Python | `content/python-basic/` |
| Advanced lessons | `content/advanced/` |
| Lectures and slide decks | `content/lectures/` |
| Research-focused material | `content/research-highlights/` |
| Other follow-up material | `content/post-school-materials/` |

Keep files belonging to one lesson together. Put lesson-specific datasets in
that lesson's `data/` folder; put reusable datasets in `datasets/`. Relative
links such as `data/example.csv` continue to work after publishing.

## What happens automatically

- `.qmd`, `.Rmd`, `.rmd`, and `.ipynb` files are rendered as pages.
- `.html`, `.pdf`, and `.pptx` files are copied and linked through generated
  wrapper pages.
- The navigation menu is regenerated from the folder contents.
- Browser-executable copies are created only for notebooks listed in
  `browser-executable.toml`; ordinary notebooks remain static and safe to
  publish.

Use a clear filename and add a title. For QMD/R Markdown, add `title:` to the
YAML front matter. For a notebook, set `metadata.quarto.title` when possible.
Otherwise the filename becomes the menu label.

Do not upload `_site/`, `generated-live/`, `generated-pages/`, or local cache
folders. They are build products and are regenerated by GitHub Actions.

## File size and licensing

The GitHub browser uploader accepts files up to 25 MiB each. Larger files need
maintainer assistance or a different hosting plan; GitHub Pages should not be
used as a large-file archive. In particular, Git LFS files are not suitable for
the Pages deployment. For a large deck, prefer a compressed teaching extract,
an external download link, or ask a maintainer to add it through the appropriate
repository workflow.

Datasets are checked at 20 MiB per file and 100 MiB total. Submit only material
you have permission to redistribute, and remove credentials, private data, and
machine-specific absolute paths.

## Cannot open a pull request?

Use the **Material submission** issue form. Attach small files or provide a
download link, choose the destination section, and a maintainer can place the
material in a branch for review.
